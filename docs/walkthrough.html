Step 1

What you need

  • A Claude plan that includes Claude Code: Pro, Max, Team, Enterprise or a Console account. The free plan doesn't include it.
  • Your GitHub account with two-step sign-in on (GitHub → Settings → Password and authentication). Before launch, move to GitHub Pro (about US$ 4 a month) so the private repo can protect main.
  • One iPhone and one Android phone for testing. An older, cheaper Android phone shows performance problems a new one hides.

Store accounts: start these early

US$ 99per year · Apple Developer Program. Needed from the first iPhone test build (Phase 3).
US$ 25once · Google Play Console. A new personal account must run a 14-day closed test with 12 testers.
D-U-N-Snumber for a company app. Enroll as the company in both stores, not with a personal account.

Install on your computer

  1. Git, from git-scm.com. On Windows, Git for Windows.

  2. Claude Code, then open a new terminal, run claude --version, and run claude once to log in. The kit needs 2.1.284 or later (claude update).

    # macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

  3. The GitHub CLI from cli.github.com, then gh auth login.

  4. Node.js LTS from nodejs.org.

  5. Android Studio, for the Android emulator and SDK. On a Mac, Xcode for the iOS simulator. Without a Mac, Phase 2 picks a cloud build service and you test iOS through TestFlight.

Nothing to install

Open claude.ai/code, connect GitHub, and make sure the Claude GitHub App can see webappstarterv2. Each session clones the repo fresh, so Claude only sees what you've pushed.

The cloud machine runs Linux with no simulator. Use it for Phases 0, 2, 6, 7 and 9, backend work and unit tests. Screens and device checks need the terminal or a Local session in the desktop app.

Step 2

Your repository

Pick how you'll use it:

One app, this repo

Build your app right here. Good for your first project.

A new repo per app

In Settings, tick Template repository. Then for each app: Use this template → Create a new repository, set it to Private.

git clone https://github.com/kaiquehonorato/webappstarterv2.git
cd webappstarterv2

If the Claude GitHub App only has access to selected repositories, add any new one: GitHub → Settings → Applications → Installed GitHub Apps → Claude → Configure → Repository access.

From the first session, .claude/settings.json stops Claude from reading .env files and signing keys, force-pushing, pushing to main and running rm -rf. It asks before database resets, production deploys, store submissions and over-the-air updates.

Step 3

Describe your idea

These 11 answers go into prompts/00-kickoff.md. Short answers are fine, and "not sure" counts: Claude asks about it. The builder below makes the full prompt for you.

Four answers shape the plan the most
  • Who installs it. A staff-only app can skip the public listing, landing page and SEO, and use a private store route.
  • Platforms. Each one adds testing, review and store work. Starting with one is a real option.
  • Users and where they are. Ireland and the GDPR are the default. Children, even by accident, add extra protections.
  • Limits. Budget and hours decide the framework, build service, hosting and v1 scope.

Step 4

Opus at high effort, because the scope and risk decisions here shape every later phase. Use xhigh for health, money or children.

# from the project folder
claude --model opus --effort high

Then paste the prompt from Step 3 as your first message.

  1. At claude.ai/code, choose webappstarterv2 in the selector below the message box.

  2. Send /model opus, then /effort high.

  3. Paste the prompt from Step 3.

Step 5

The discovery conversation

1 to 2 hours of talking. No code is written in this phase.

  1. Reality check

    Claude restates your idea and first asks if it needs to be a store app at all, compared with a web app that works well on phones. Then it names the riskiest assumption and the smallest version that would test it.

  2. Interview

    A few questions at a time, each with a recommended answer: roles, platforms, distribution, store accounts, use cases, permissions, offline use, personal data, money, look and feel, abuse, and who handles problems after launch.

  3. Choose v1

    Three scopes (minimal, balanced, ambitious) with effort, monthly cost, one-time costs and main risk. Claude recommends one; you choose.

  4. Documents

    Claude writes SPEC.md, docs/GLOSSARY.md and docs/ROADMAP.md.

  5. Gate

    A 10-line summary, open questions, what to cut first, and which store accounts to start now. Read SPEC.md, ask for changes, then reply approved. Claude opens a pull request: check Files changed, then Merge pull request.

While you answer

  • "Use your recommendation" is a valid answer.
  • Paste screenshots of apps you like. Keep them: Phase 1 asks for 2–3.
  • If it drifts: "Summarize what we have and ask only what blocks the spec."
Step 6

Every phase after that

Same loop each time: fresh session with that phase's model and effort, paste its prompt, answer and approve, check the evidence, merge. Phases marked your computer need a simulator or phone.

    These are starting points. If Claude skips work, raise the effort one step. If it tries hard and is still wrong, switch to Opus. Details in docs/models-and-tokens.md.

    Step 8

    Habits that keep quality high and cost low

    1. One phase or one Issue per session. /clear between unrelated tasks.Start a new session for each. The plan lives in files, so a fresh session loses nothing.

    2. Corrected Claude twice on the same thing and still wrong? Start fresh with a better prompt.

    3. Don't accept "done" without evidence: a test, a screenshot from each platform, or a command and its output. Ask which checks ran on a real phone.

    4. Never paste passwords, API keys, signing keys or store credentials into the chat. They go in your host's settings, the build service, GitHub secrets, or a local .env you edit yourself.

    5. docs/ROADMAP.md always shows where you are and what comes next.

    6. Press Esc to stop Claude mid-task; Esc twice or /rewind to go back. claude --continue reopens the last session.

    7. Read docs/vibe-coding-mistakes.md once: the 52 common ways AI-built apps fail, and the guardrail for each.

    Step 9

    When something goes wrong

    What you seeWhat to do
    claude: command not found after installingOpen a new terminal. If that fails, run claude doctor.
    The repo isn't listed at claude.ai/codeGive the Claude GitHub App access to it (Step 2).
    Claude asks permission to run a commandRead it first. Approve normal dev commands; decline anything that deletes data, touches production or submits to a store unless you asked.
    Claude can't read .env or a key fileOn purpose. Fill those in yourself; Claude works from .env.example.
    Claude couldn't run the simulatorYou're in a browser session or it isn't installed. Run that check on your computer or in CI.
    Works on the simulator, not on your phoneAsk Claude to reproduce it on the phone first. Release builds, slow phones and real networks behave differently.
    A store rejected the submissionPaste the rejection into a fresh Opus session; ask for the guideline cited, the smallest fix and a reply to the reviewer.
    The session is slow or loses track/compact with what to keep, or start fresh.
    A decision doesn't make sense"Explain this as if I'm new to it" or "Show me the ADR for this".
